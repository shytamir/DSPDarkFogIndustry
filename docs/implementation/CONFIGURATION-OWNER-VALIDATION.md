# Configurable recipes: owner check

[PROJECT](../PROJECT.md) owns candidate selection, technical readiness and your
acceptance decision. This procedure concerns configurability, not publication.

## Candidate and preparation

Use **DSPDarkFogIndustry 0.9.30**, from
[run 38405672271](https://github.com/shytamir/DSPDarkFogIndustry/actions/runs/38405672271),
attempt 1, source `5c0cdda26e5f08d378795c604afc83787a046617`.
Download the artifact named `DSPDarkFogIndustry-0.9.30.5c0cdda26e5f.zip`.
PROJECT records the independently verified package and DLL hashes.

The inspected native reference is DSP **0.10.35.29131**, with BepInEx **5.4.17**.
Use a disposable checkpoint and a test profile with this plugin and BepInEx.
Keep both your original save and its configuration. Import the local package into
Thunderstore Mod Manager, or follow its included manual-copy instructions; avoid
loading a second copy of the plugin. No active configuration is shipped in the ZIP.

Start DSP once, then exit. Use the generated
`BepInEx/config/dark-fog-industry.cfg` in that same profile for both editors below.
The repository's offline layout sample is generated by `./build.ps1` at
`artifacts/configuration-checks/reference.cfg`; its names/IDs are test data, so do
not install that sample as your game configuration.

## One default pass

Open the generated file in Notepad, then in Thunderstore Mod Manager's config
editor. Check that the six numbered recipe groups appear first, followed by item,
technology and machine ID references. Search for an item name and its ID; check
that the machine group lists only smelters, assemblers and chemical plants. Names
should follow the game's active language. Note the manager version used.

On the disposable checkpoint, confirm the default recipes and unlocks remain
available as expected. At full power, with continuous supply and clear outputs:

| Default recipe | Basic rate, no proliferation | Upgraded rates, no proliferation |
| --- | --- | --- |
| Energy Shard | Arc Smelter: 120/min | Plane Smelter: 240; Negentropy Smelter: 360 |
| Middle four recipes | Assembler Mk.I: 60/min | Mk.II: 80; Mk.III: 120; Re-composing Assembler: 240 |
| Core Element | Chemical Plant: 60/min | Quantum Chemical Plant: 120 |

Allow buffers to settle before measuring. Check that only the assembler recipes
allow hand replication. Existing proliferation behavior should remain: default
Dark Fog Matrix and Silicon-based Neuron allow speedup only; the other four also
allow extra products. This candidate retains the earlier detector hotfix unchanged;
report any sandbox-mode or abnormal-history regression separately.

## Edit, restart and custom production

Before edits, use the **old configuration** to stop and empty affected machines,
clear their selected recipes, cancel affected handcraft orders, and save. Exit DSP.
Make these edits, leaving other fields at their defaults:

| Recipe section | Settings |
| --- | --- |
| 01 — Energy Shard | `MachineId = 2319`, `OutputCount = 4`, `OutputPerMinute = 120` |
| 02 — Dark Fog Matrix | `TechnologyId = 1133`, `MachineId = 2318`, `OutputCount = 2`, `OutputPerMinute = 90`, `Input2ItemId = 1013`, `Input2Count = 3` |
| 06 — Core Element | `MachineId = 2317`, `OutputCount = 3`, `OutputPerMinute = 90` |

Use Notepad for one edit and the manager for another, then confirm each editor sees
the other's saved values. Restart DSP. Expected consumption per completed batch:
recipe 01 uses one Fractal Silicon; recipe 02 uses one Energy Shard and three
Fractal Silicon; recipe 06 uses one Negentropy Singularity and one Antimatter Capsule.
The output counts are 4, 2 and 3 respectively.

| Custom recipe | Basic rate | Upgraded rates |
| --- | --- | --- |
| 01 | 120/min | 240/min; 360/min |
| 02 | 90/min | 120/min; 180/min; 360/min |
| 06 | 90/min | 180/min |

These are unproliferated rates. Choosing an upgraded ID must not change the basic
rate. With all ingredients fully sprayed by Proliferator Mk.III, extra-product mode
should yield 1.25 times these rates at unchanged ingredient consumption; acceleration
mode should yield twice these rates with twice the ingredient consumption. Test the
basic and one upgraded facility from each family. None of these examples reaches
the native one-cycle-per-update ceiling.

Recipes 01 and 02 now share Particle Control. On a checkpoint where that research
is incomplete and neither recipe is already unlocked, both should unlock on its
completion. Loading a checkpoint that already completed Particle Control should
grant both. Previously saved recipe unlocks must remain if you later move the gate.
The four assembler recipes should still permit hand replication.

For an output/family change, prepare and save again under the current settings.
Change recipe 02 to `MachineId = 2309` and `OutputItemId = 1606`. After restart it
should produce Crystal Shell Sets in chemical plants at 90/min in the basic plant
and 180/min in the quantum plant, two per batch. It should no longer allow hand
replication or selection in an assembler. The emptied original building should
remain empty with its recipe cleared; changing the config does not convert it.
Restore the previous configuration/checkpoint together after this check.

## Corrections and persistence

With DSP closed and affected machines/queues prepared, use the default recipe 02
settings except `OutputPerMinute = 61`. Restart: the saved value should be **60**,
with `OutputCount` still **1**, and the log should name the field, 61, 60 and the
rate correction. Then try these independent edits:

| Edit | Expected result |
| --- | --- |
| An unused row has `ItemId = 0`, `Count = 8` | Count becomes 0; the row remains unused |
| `OutputCount = nonsense` in recipe 02 | Default count 1, with a specific log explanation |
| `MachineId = 2901` on the native catalogue | Nearest eligible ID 2319; the recipe becomes smelting |
| Edit a name in the item reference | Recipe settings are unaffected; the native label returns at startup |

Check other valid fields survive and the next restart produces no further
correction. The excluded-machine result assumes the native catalogue; another mod
may add a nearer eligible machine. File syntax errors and write permissions are
explicit file errors, not whole-file recovery cases.

Do not use huge recursive crafting chains as an overflow-safety test. As directed,
native raw-material calculations and accumulated handcraft queues retain their
limits; automatic correction covers recipe fields and machine operation.
