### MVP-01 — Resolve the integration seam

**Outcome:** Establish a bounded, evidence-backed way to register six native recipes.

**Entry:** Owner authorizes implementation scope in PROJECT after roadmap review.

**Scope:** Inspect the chosen registration mechanism, initialization order, ID
capacity/collisions, save behavior, and local/hosted reference options. Select and
pin dependencies only after source and reference checks. Resolve the investigation
questions in the technical basis before dependent implementation.

**Definition of done:** A short technical decision names the selected mechanism,
dependencies, six stable recipe IDs, initialization/save hooks, reference strategy,
and remaining owner observations. Fixed recipe inputs, gates, placement, and rates
are mapped to authoritative native data. The route has no manufacturing or research
cycle requiring an unavailable Fog product/building.

**Evidence / stop:** Record exact native/dependency identities and the source of
each resolved question in the technical basis. Verify baseline prefab speeds and
time units before fixing durations. Stop dependent work if registration order,
stable IDs, the hosted reference route, or acyclic progression cannot be established;
report the specific conflict and smallest owner decision. Do not reopen settled
balance choices merely because a native mechanism needs investigation.

**Exclusions:** No framework, full game emulation, runtime compatibility claim,
balance change, deployment, or new product feature.
